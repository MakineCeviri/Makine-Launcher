## Dal düzeni — dikkat

`main` ile `dev`'in **ortak geçmişi yok**. `main` varsayılan dal, 2026-03 başlangıçlı ayrı bir geçmiş,
sonrasında yalnız Dependabot PR'ları almış. v0.1.2 / v0.1.3 / v0.1.4 etiketlerinin hepsi `dev`'de.
"dev → main merge" bu yüzden yapılamıyor. Sonuçları:

- Zamanlanmış GitHub iş akışları yalnız `main`'den çalışır → böyle bir iş `main`'e de PR ile konmalı
  (`main` korumalı, force-push yok).
- Dal stratejisini düzeltmek (ör. varsayılan dalı `dev` yapmak) sahibinin kararı; dokunulmadı.

## Bu dönemde öğrenilen tuzaklar

| Tuzak | Ne yapmalı |
|---|---|
| `sentry-cli` repo kökündeki `.env`'i okur; oradaki `SENTRY_ORG` `.sentryclirc`'yi ezer | Org/projeyi komut satırında ver (`upload_symbols.py` veriyor) |
| Sentry API "200" döner ama ayarı uygulamaz (anahtar `rateLimit`, eski planda) | Her ayardan sonra geri oku |
| Sentry token'ları API'den üretilemez (yalnız tarayıcı oturumu) | Token'ı sahibi kopyalar, `set_sentry_token.py` |
| `--selftest-telemetry` yalnız dev yapısında derlenir | Yayın exe'sini oturumun Sentry'ye ulaşmasıyla doğrula |
| D1'de `wrangler d1 migrations apply` eski migration'ları ve seed'i yeniden çalıştırır | Tek dosya: `wrangler d1 execute --file` |
| `git push` Git Credential Manager penceresini bekleyip asılı kalır | `git -c credential.helper= -c 'credential.helper=!gh auth git-credential' push …` |
| Git Bash `origin/main:yol` biçimini Windows yolu sanıp bozar | `MSYS_NO_PATHCONV=1 git …` |
| Çıplak ortamla (`env -i`) çalıştırılan exe, çalışma dizinine `%SystemDrive%/` klasörü açar | `SYSTEMDRIVE` ver ya da repo dışında çalıştır |
| Çıplak PATH'te `timeout` Windows'un `TIMEOUT.EXE`'sine çözülür | `/usr/bin/timeout` |
